## D. Match and news pipeline

Existing match flow is server-loaded store/catalog → schedule client props → crawlable `/matches/[id]` anchors → source/catalog detail. The unused `components/matches/MatchCard.tsx` still targets legacy routes, but active schedules import `components/MatchCard.tsx`; it was not incorrectly replaced.

Existing news flow is publisher/Google RSS adapters → resolver/normalization → `validateNewsCandidate` → ingest/dedup → gateway store → published/latest/archive queries → public API and server-rendered listing/article templates. Source articles display attributed excerpts and original links; manual articles can display body paragraphs. Tests cover ingestion, failures, deduplication and preservation of saved records. Those are fixture/unit results, not evidence that sandbox provider requests succeeded.

The bundled store contains 37 match records and zero news items. A valid local real-article HTTP test could not be performed without injecting fixtures; no fabricated story was inserted. Live news list content exists despite the empty repository snapshot, so “the production news pipeline is empty” would be an incorrect conclusion. One live broken article destination was reproduced, but the production storage boundary could not be inspected safely here.

Storage investigation: `lib/db/durable-store.ts` explicitly selects an instance-local temporary JSON file on serverless runtimes, and `lib/storage/index.ts` offers no shared cloud backend. That is a verified repository-level limitation: a record fetched on one instance is not necessarily available to another. It is consistent with the observed list/article mismatch but does not conclusively prove the production cause without deployed runtime/configuration evidence. Refreshing missing articles from RSS on each detail request would not guarantee recovery of older stories and could turn requests into expensive fetches; it was not used as a superficial fix. A shared-storage change would affect the wider store and require a separate reviewed migration plan, so no storage, streaming or Cron configuration was modified.

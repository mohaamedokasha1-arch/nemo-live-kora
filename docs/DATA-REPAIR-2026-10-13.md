## المشاكل والإصلاحات المنفذة

1. **كرون مفتوح ونجاح كاذب:** `update-matches` أصبح محميًا؛ يرسل run id والتوقيت والعدّادات وحالة التخزين. فشل البيانات/عدم دوام التخزين = 503. missing secret = 500 مشخص، secret غير صحيح = 401.
2. **Vercel JSON غير دائم:** الكتابة كانت تفشل بصمت. أصبحت كتابة ملف محلي عبر temporary + rename مع حالة قابلة للقراءة وتسجيل الخطأ. لم تتحول إلى قاعدة بيانات خارجية. المسار المجدول لا يدّعي التخزين الدائم على Vercel حتى لو نجحت كتابة محلية.
3. **حالة live تتفوق على finished:** أزيل ترتيب الحالات المعيب؛ ملاحظة حديثة نهائية تحل محل الجارية، والملاحظات الأقدم/الفارغة لا تمحو النتائج. لا تخمين للحالة المجهولة.
4. **دمج واسع:** المفتاح الآن يشترط الموسم وUTC kickoff المؤكد مع ترتيب الفريقين؛ لا يزيل FC/SC من أسماء الفرق غير المعروفة، ويحافظ على Unicode. وقت غير مؤكد لا يُدمج عبر مصادر بالتخمين. tradeoff مقصود: قد تبقى نسختان عند اختلاف موعد أو اسم حتى تُثبت مطابقة المعرفات.
5. **تتبّع بيانات:** provenance على مستوى الحقل الأعلى للمدخلات الجديدة والتعديلات، لا اختراع تاريخ للمعلومات القديمة. ليس provenance لكل جزء من score ولا نظام أولوية موثوقية كاملًا.
6. **HTTP:** timeout يمتد لقراءة body؛ retries محدودة لـ5xx/429؛ invalid JSON لا يدخل cache؛ cache مفصول بحسب بصمة headers/parser ومحدود 500 مدخل. ليست هذه إدارة quota أو pagination شاملة.
7. **اكتشاف:** حفظ فهرس Football-Data الفعلي عندما يصل بدل حفظ الموسم وحده، واختبار مسابقة جديدة غير مكتوبة في القائمة. لا ادعاء اكتشاف كل بطولات المزودين.
8. **الصفحات:** مسار `/matches/[id]` يعرض الآن سجلات المخزن خارج الكتالوج: الفريقان والشعاران، البطولة/الموسم/الجولة عند وجودها، التاريخ/التوقيت المؤكد، الحالة والنتيجة والملعب والأحداث المتاحة والتحديث والمصادر والمباريات المرتبطة. روابط بيانات داخلية لا تغيّر مسار البث. aliases الكتالوج تحوَّل إلى صفحتها الأصلية.
9. **SEO:** canonical وH1 ومحتوى SSR للتفاصيل الجديدة؛ sitemap يضم السجلات ذات الوقت المؤكد ضمن نافذة محدودة دون تكرار كتالوج. لا بيانات منظمة زائفة لملعب/سعر/عنوان/نهاية متوقعة. لم ندّعِ فهرسة Google أو نستخدم Search Console.
10. **الأخبار:** HTTP 200 دون مواد قابلة للنشر ليس نجاح ingestion. آخر الصالح يظهر عند غياب جديد مع توضيح القِدم؛ آخر فشل يظهر. العناوين الضعيفة تربط بالناشر بدل التفاصيل. معيار indexability القديم (طول مقتطف) ما زال يحتاج سياسة قيمة تحريرية أصلية؛ لم ننشئ محتوى اصطناعيًا لإرضائه.
11. **التزامن والرصد:** single-flight للمزامنات داخل العملية؛ عدّادات insert/update/unchanged لكل مزود مباريات وأوقات نجاح البيانات/الفشل في سجلات المصادر. ليس قفلًا موزعًا ولا تحقق read-after-write من قاعدة إنتاج.

## الاختبارات والنتائج المحلية

- بعد الإصلاح: **72 اختبارًا ناجحًا، صفر فشل** (baseline 64).
- `npm run build`, `npm run typecheck`, `npm run lint`: نجحت. البناء يشمل typecheck أيضًا.
- اختبار فشل المزودين جميعًا يثبت استجابة 503 مع runId وسجل تنفيذ، صفر جلب وعدم تغيير المباريات المخزنة.
- اختبار الكرون يمر خلال adapter → normalization → upsert → **قراءة JSON مكتوب في مجلد اختبار مؤقت**؛ اختبار GET/POST لمباراة fixture واحدة والتأكد من نتيجتها 1–0 وعدم التكرار. هذا ليس سجل مباراة حقيقية أو اختبار إنتاج.
- اختبار اكتشاف **بطولة fixture واحدة** وإدراجها مرتين يبقي سجلًا واحدًا. fixtures فقط.
- اختبارات الدمج: live → finished، منع الرجوع بملاحظة أقدم، null scores، اختلاف وقت اللقاء والأسماء وعدم تأكيد الموعد.
- اختبارات HTTP: retry 503، cache مع مفاتيح مختلفة، عدم caching JSON معطوب، وفشل fixtures 403 رغم نجاح competitions 200.
- اختبار الأخبار الإضافي: RSS فارغ 200 → `ok=false`، صفر نشر، والأخبار السابقة لم تتغير. الاختبارات الموجودة تغطي RSS synthetic، التكرار والتحويلات غير الآمنة والتوقيت والحالة ومهل TheSportsDB والـSEO.
- **لا يوجد اختبار حي ناجح لpagination أو ترتيب/هدافين/تشكيلات أو جلب جميع المواسم.**
- `npm audit`: **5 high** في شجرة tooling (`@next/eslint-plugin-next`, `eslint-config-next`, `fast-glob`, `micromatch`, `braces`). لم نطبق force upgrade غير مدروس؛ مخاطرة متبقية.

## حالة الجدولة قبل وبعد

`vercel.json` لم يتغير: `0 5 * * *` → `/api/cron/update-matches` فقط. لا سجل Vercel متاح يثبت تنفيذها قبل أو بعد. الكود قبلها كان غير موثق ويُرجع ok دائمًا؛ بعده يحمي التنفيذ ويكشف فشل البيانات والتخزين. **الكرون لم يُختبر على الإنتاج ولم يُنشر هذا الإصلاح.**

الأخبار ما زالت on-demand أو endpoint مستقل؛ لم نغيّر جدول الاستضافة دون إثبات حدود الخطة أو اكتمال persistence. full sync قد يتجاوز 60 ثانية مع timeouts المتسلسلة؛ يلزم queue/batching بميزانية عامة قبل اعتماده.

## ما بقي غير مكتمل ولماذا

- ربط مخزن دائم مع معاملات وقفل موزع ومهاجرة آمنة للبيانات. لا خدمة مهيأة ولا تفويض شراء؛ واجهة التخزين الحالية synchronous وتتطلب تعديلًا بنيويًا صحيحًا، لا ادعاء أن ملف lambda قاعدة بيانات.
- تحقق إنتاجي read → normalize → persist → readback → SSR، وسجلات كل مزود والحصص والتغطية والحقوق. الشبكة والصلاحيات الحالية لا تسمح بذلك.
- حل روابط Google الحديثة/مصدر RSS مباشر مرخص. الإبقاء على الرفض أفضل من اختراع ناشر أو خبر. لم نصلح استقبال أخبار فعلية في الإنتاج؛ السبب البنيوي موثق.
- اكتشاف شامل تدريجي للمسابقات والمواسم مع cursors/pagination وحدود خطة مثبتة؛ الإحصاءات والهدافون والتشكيلات والحكم والمدينة/الدولة والسعة وH2H غير متاحة بشكل متكامل.
- نموذج أولوية لكل حقل وهوية مشتركة عبر كل providers، مع مصدر كل جزء وتوقيت observation لا مجرد fetched time.
- صفحتا بطولة/فريق، معيار تحريري أصلي للأخبار، فحص جميع aliases/filters وStructured Data في أدوات Google. لا Search Console، فلا ادعاء فهرسة.
- معالجة التنبيهات الأمنية في تبعيات أدوات التطوير.
